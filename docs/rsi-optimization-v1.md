# F02：先判断值得改什么，再决定如何开始

运行 `npm run rsi:optimize`，用十来行结果查看整个流程。默认不调用模型；示例费用、质量见证都是人工诊断数据，不是实验成绩。

| 要回答的问题 | 机制给出的结果 |
| --- | --- |
| 哪些地方重复花费模型计算？ | 按结构与组件归组，列出涉及的独立任务和完整请求 |
| 能交给 Runtime 吗？ | 必须有完整请求的确定性见证；混有语义判断、质量未评审或归因不明时，输出“待核验” |
| 值得开始吗？ | 用整个登记任务群体的命中频率估计收益，扣除预计开销；不够就跳过，值得试验的优先排列 |
| 如何开始？ | 固定修改组件、允许的 patch 类型、父版本、训练/留出任务及输入、评审标准、停止条件 |
| 改完是否有效？ | 同输入、同模型/工具条件比较基线与候选；检查质量、实际版本采用和所有请求费用 |
| 可以发布吗？ | 效果报告经独立审核后，再通过原有认证、证据与原子提交检查；任一失败就不发布 |

统一例子仍是 A 科研报告、B 报名汇总共享局部计数，C 只写邀请。A/B 的计数反复出现，只能提出优化候选；若同一次模型请求还在判断“哪些报名有效”，就不能把整次请求算作可消除。C 不命中也保留在频率分母。D/E 是另外的开发诊断输入，用来说明留出对照，不能把同一输入换个任务名冒充独立验证。

输出分为两组：**开始前**是值得试验／待核验／跳过；**修改后**是接受试验结果／不接受／证据不足。接受只支持进入受控版本审核，不代表已经证明后续任务累计降本。

## 本轮实际完成与边界

- Python 离线机会评估与配对计量；TypeScript 在线检查启动和发布条件。两端共用 Schema，按精确记录字节绑定。
- 演示与回归覆盖：混合语义、任务换名、训练/验证重叠、数据/配置变化、未加载候选、质量下降、额外开销抵消收益、漏请求、失败/重试与未知费用。
- 上一轮原生真实记录只作历史重放。缺少完整任务质量评审和整次请求可替代性见证时，输出“待核验”，不自动启动。

尚需 F03 接真实任务与独立评审器，F05/F08 生成真实修改并验证下一任务采用。当前不自动推断语义可替代性，不实现通用优化器，不启用生产。历史同场景重复、局部计数正确和人工认证标记，都不能替代这些工作。

<summary>接口、计量与接入约定（需要实现时再读）</summary>

1. 可信导出器输出 `optimization_run`、原始 `provider_request` 投影和 `optimization_boundary`。边界分类须有轨迹见证；工具名、频率或相似度本身不证明整次请求可删。`quality_sha256` 绑定冻结评审标准，评审结果与来源由独立宿主核验。
2. `scripts/rsi-optimization.py assess --source SOURCE --policy POLICY` 输出 `optimization_assessment`。策略中的样本门槛和未来任务数只是显式开发假设，不能替代 G2/G3 的论文门槛。
3. `startRsiOptimization` 只接受宿主独立批准的 assessment 摘要及当前数据/策略/版本，产生 `optimization_plan`。留出输入摘要不能与训练重复；评测器代码版本一并冻结，由宿主独立核查。优化器不能修改评测器、质量标准或权限检查；该计划不授予工具、任意代码或外部写权限。
4. F05/F08 根据计划产生现有 `candidate_patch`；只有计划允许的组件/类型、训练范围与父版本可进入对照。测试集禁止参与选择或修订。
5. `scripts/rsi-optimization.py evaluate --plan PLAN --policy POLICY --candidate PATCH --measurements MEASUREMENTS` 输出 `optimization_verdict`。每个留出任务都须有两臂；所有尝试、额外诊断/提案/评估/维护请求均须登记。重试不增加独立任务分母。本轮默认不允许新增质量失败，可在启动前明确修改并冻结策略。
6. `publishOptimizedRsiUpdate` 要求效果报告独立批准、原验证报告包含全部必需检查，并复用 `publishRsiUpdate`。通用旧 API 保留兼容；新优化路径必须显式使用本入口。发布和回滚仍依赖真实组件适配器与原生守卫。

计量同时报告：

- 配对比较差额 `B − C − O`：基线任务费用减候选任务费用及额外机制请求费用。它不是账单净入账节省。
- 实验实际总支出 `B + C + O`：两臂验证也花钱，全部保留。未来摊销估计为 `(B − C) / 留出任务数 × 假设未来任务数 − 实验总支出`，非已实现收益。两项收益检查均须满足冻结门槛。
- 人工修订/评审秒数和耗时在每个运行记录另列；没有约定价格就不折算为美元，当前门槛针对模型费用/请求。账单实付仍需核对。

请求按 `(ledger_ref,id)` 去重，booking 被终态替代；已知费用的失败计入成本，未知保留 `null`、已知费用小计与预留。清单遗漏、双重分配、相互冲突的终态会失败关闭。`expected_run_ids` 必须来自可信运行登记册；不能由优化器用挑选后的成功列表自报。当前提供清单校验，尚未对接完整 F03 登记册，无法凭一个自报 JSON 证明没有省略历史。

所有记录都是证据载体。输入本身通过格式校验，不表示证据或评审已经可信；在线批准摘要必须由独立宿主提供，不能接受候选自报。
